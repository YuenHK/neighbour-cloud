# GAIA／鄰伴命名及功能對照提案

本文件只供分析和介紹，沒有改平台名稱、程式路由、模型、資料或機械人。用戶提供的巴哈頁面在本次讀取回 403，公開索引亦未找到足夠原文，沒有假稱已讀該討論。以下遊戲設定以 PlayStation 官方故事回顧為主；九個子功能的詳細職責採遊戲內文字資料點《The Subordinate Functions》的社群轉錄，明確區分官方網站與二級載體。

《地平線》的 GAIA 是協調整個地球復育計畫的核心 AI，透過專職子功能完成不同工作。這與鄰伴「把居民對話、屋苑資訊、巡查線索及職員跟進連起來」的設計有明顯相似之處；這是本專案的架構類比，不是聲稱現有平台具有遊戲中的自我意識或全面自主能力。[PlayStation 官方故事回顧](https://www.playstation.com/en-us/editorial/horizon-zero-dawn-the-story-so-far/)

## 建議名稱層次

- 整個平台：**GAIA 蓋亞智慧社區平台**。
- 居民眼前的數字人：繼續叫 **鄰伴**，作為 GAIA 與居民接觸的親切入口。
- 職員功能：用「中文功能名稱 · 英文代號」，例如「居民關懷 · ELEUTHIA」，方便不熟悉遊戲的職員使用。
- 技術做法：一個總分流流程協調多個專職模組，共用 Gemma、Microsoft 語音及現有資料服務。模組名稱穩定，服務商維持目前選擇；不用為九個名稱另外開九個模型或增加 API 呼叫。

## 九個職能與本專案的對照

以下「遊戲職能」是設定摘要；「鄰伴對照」全部是我們的設計推論。[遊戲內資料點的社群轉錄](https://horizon.fandom.com/wiki/The_Subordinate_Functions)

| 名稱 | 遊戲原本職能 | 鄰伴可對應的角色 | 現況與界線 |
| --- | --- | --- | --- |
| **APOLLO** | 保存知識，教育新生人類 | **知識與記憶**：屋苑資料、網上搜尋、會話上下文、明確長期記憶 | 多項已有；記憶沿原有明確保存及三分鐘交接規則，不把所有聊天永久記下 |
| **ELEUTHIA** | 在搖籃設施孕育人類 | **居民關懷**：陪伴、了解需要、情緒／危機分級、交給職員跟進 | 關懷與個案流程已有；是「照顧人」的理念類比，不是醫療診斷或孕育功能 |
| **HEPHAESTUS** | 設計、製造及維護機器與工廠 | **機械工坊**：EP／S1 適配、設備狀態、巡查排程、數字人模型裝配 | EP 原有人手控制與圖庫已有；S1、定位及自主行車仍有離機／真機待驗部分，平台不會製造實體機器 |
| **MINERVA** | 產生並廣播 Faro 機群停用碼 | **受控通訊與停止保護**：登入權限、控制租約、失聯停止條件、簽署放行 | 有現成控制與權限保護；現實功能是對停用／協調理念的延伸，不是替機器破解權限 |
| **DEMETER** | 恢復植物，修復土壤及環境 | **社區環境**：垃圾、清潔、公共地方環境回報 | 查詢／清潔跟進及巡查候選已具基礎；垃圾視覺精準度待實景驗收，綠化／植物辨識未完成 |
| **POSEIDON** | 淨化地球水域 | **水務觀察**：漏水、積水、排水異常候選與職員覆核 | 住戶漏水個案已有；影像積水候選不等於確認水管故障，實景驗收仍需完成 |
| **AETHER** | 淨化、穩定大氣 | **空氣與煙霧觀察**：煙霧／火警候選、日後接空氣感測 | 目前是疑似現象與人工覆核方向；沒有宣稱已安裝 PM2.5／煙霧感測器，亦不把畫面分析當消防認證 |
| **ARTEMIS** | 恢復動物物種 | **生態共處**：將來可留給動物受困、寵物或社區生態觀察 | 現在沒有直接對等功能，應列未來項目；不要硬改成追蹤／識別居民或「狩獵可疑人士」 |
| **HADES** | 撤銷不適合生命的復育結果，讓計畫重試 | **故障隔離與復原**：停用出錯部件、回復已知良好版本、從備份恢復 | 有界重試、維護閘門及復原機制已有；這是改寫後的正向工程比喻，不刪居民資料、不清 quota、不代表整個系統會自行重置 |

原遊戲的 HADES 與 HEPHAESTUS 職責亦由 PlayStation 官方回顧直接說明，這兩項不應被解作「原本就是惡意 AI」或「機械人進攻功能」。[官方回顧](https://www.playstation.com/en-us/editorial/horizon-zero-dawn-the-story-so-far/)

## 最像我們的地方

1. **一個總體目標，多個專職分工**：GAIA 照顧整體生態；鄰伴把居民身心、屋苑實體環境及資料跟進放在同一服務流程。
2. **數字人的溫度配合機械人的觀察**：鄰伴聽居民說話，機械人提供現場線索，管理員負責核實及安排實際協助。
3. **資料與行動連起來**：知識／記憶幫助理解問題，個案讓職員接手，進度又可回到居民對話；不是只有聊天畫面。
4. **分工清楚及可恢復**：每個模組有自己的輸入、輸出及權限。某個服務失敗時，其他可用服務盡量保留；重要資料和實體控制由原有保護機制處理。

## 可以直接用的學生介紹稿

> 我們建議把整個平台稱為「GAIA 蓋亞智慧社區平台」，把社區看成一個需要大家照顧的小生態圈。蓋亞是協調中心，「鄰伴」數字人負責聆聽居民、查資料和了解需要；巡查機械人幫忙觀察現場，再把需要處理的事交到管理人員手上。不同子系統各有分工，例如 APOLLO 整理知識，ELEUTHIA 關顧居民，HEPHAESTUS 管理機械人。它們共同幫助職員更早看見需要、更快安排支援，讓居民覺得有人關心，也讓社區生活更加安心。

介紹時補一句實況：「居民對話、查詢及個案跟進已可使用；機械人的 S1 接入、定位與自主行車仍在離機測試及現場驗收階段。」這可保留願景，同時符合現況。

## 命名與呈現注意

- 現在適合先稱「子系統／功能模組」，若稱「子代理」，應說清楚是工作分工，不是已運行九個有獨立推理、記憶和權限的 AI。
- 可以在職員頁用「正常／受限／離機待驗」呈現各模組，不把遊戲裡的虛構處理密度百分比當成真 CPU 或 API quota。
- 故事中的 MINERVA 是停用碼通訊職能；本專案的權限及資安只屬類比延伸。
- 故事中的 HADES 會把復育結果歸零；本平台只借用「可控隔離及回復」概念，資料保存與刪除仍按居民同意和原有 90 日規則。
- **NEMESIS 與 CYAN 不在 GAIA 原本九項子功能名單中。** NEMESIS 是另一條故事線的集體數碼意識；CYAN 是 Firebreak／Yellowstone 的獨立 AI。如要額外借用，應清楚列作外圍構想，不把它們湊入九個原職能。
