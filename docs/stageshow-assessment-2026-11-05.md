# Stageshow：適用性與鄰伴 UI 改良建議

查閱日期：2026-11-05。這是針對官方文件及鄰伴現況的評估，未安裝到正式平台，也未更改現有 UI。

## 結論

**值得採用它的構圖及動畫驗證方法，尤其適合平台介紹、操作示範與載入過場。**居民對話和管理工作台則要按真實任務、資料與裝置重新設計。

Stageshow 是 Benji Taylor 的開源 agent skill，主要製作靜態產品圖及短篇模擬介面動畫，輸出為 React 元件。它會先決定展示位置、風格、故事與重點，再用示例和逐幀檢查修正成果。這個定位可在[作者介紹](https://benji.org/stageshow)及[官方 SKILL.md](https://github.com/benjitaylor/skills/blob/main/stageshow/SKILL.md)核對。

## 對鄰伴最有用的地方

| 可借鑑的方法 | 如何用在鄰伴 |
| --- | --- |
| 先決定視線重點，再刪減次要內容 | 求助、關懷及回報清單突出「甚麼事、在哪裏、誰要接手、下一步」，其他資訊按需要展開。 |
| 對齊字級、間距及視覺層級 | 統一搜尋欄、篩選、狀態標記與主要按鈕，減少相同重量的大框。 |
| 手機有自己的版面 | 為窄屏重排內容及操作，保留可讀字級；最後才考慮少量縮放。 |
| 每個動作有原因 | 傳送後顯示真正等候狀態；個案更新、模型切換及視窗開關有清楚過渡。 |
| 檢查整段動畫 | 查看入場、展開、切換、收合及淡出過程，找出跳位、遮擋、閃白及循環接縫。 |

官方的 `film.mjs`、`jumps.mjs` 與 `layout.mjs` 分別協助錄製／檢查動畫、找單幀跳動及檢查元件邊界。這些工具及其 Stage 元件有自身結構，接入鄰伴前需要獨立驗證，不能單憑安裝就聲稱正式 UI 已改善。

## 適配方式

鄰伴目前以 AIRI／Vue 及原生 HTML、CSS、JavaScript 運作，Stageshow 的元件套件則使用 React。適合先把它的設計檢查表、手機版面及逐幀檢查方法接到現有開發流程；需要製作獨立介紹動畫時，再評估其 React 元件。

正式居民及職員頁繼續顯示真實資料：不能把範例用的灰色佔位線、模擬游標、固定動畫進度或假成功狀態當成實際功能。載入完成便應讓用戶進入，毋須為了播放完整動畫而拖慢操作。保留減少動態、鍵盤操作、對比度、觸控尺寸、私隱及原有安全流程。

**建議次序：**先整理管理清單及圖庫的資訊層級；再檢查居民對話的等候、回覆與語音狀態；最後微調九子功能展示的節奏與逐幀過渡。每次以小範圍前後對照及隔離測試驗證，再部署。
